## Environment and method

- Windows, Node.js 24.19, Expo SDK 57, React Native web in the Codex in-app browser.
- Real UI walkthroughs used a fresh `http://127.0.0.2:8081` origin. The user's `http://localhost:8081` progress was preserved. No test records were inserted into the user's storage.
- Visual checks used 1280 × 720 and 360 × 800 viewports. The temporary viewport override was reset afterward.
- Existing documentation, strategy scope, source, tests, and Git history were inspected. Domain tests used independent reference tables and mathematical oracles, not only the implementation's own answers.
- Browser actions, deterministic regression tests, source inspection, and native bundle checks are distinguished below. A source-only fix is not represented as a physical-device observation.

## Independent correctness evidence

The [engine audit](../src/engine/QA.md) documents sources, fixtures, and limits. Reference material was checked September 20, 2026:

- [Wizard of Odds: 4–8 deck basic strategy](https://wizardofodds.com/games/blackjack/strategy/4-decks/) and [late surrender](https://wizardofodds.com/games/blackjack/surrender/) supply an independent, fixed chart oracle. **1,360 cells** cover S17/H17 × surrender on/off.
- **5,500 hand valuations** are compared against independently enumerated ace assignments.
- **3,200 seeded rounds** use arbitrary legal actions, fractional wagers, insurance choices, multiple complete shoes, and reshuffles. Independent count/accounting checks and persistence round trips verify transitions.
- [Wizard of Odds: Hi-Lo](https://wizardofodds.com/games/blackjack/card-counting/high-low/) supports the declared introductory indices. [QFIT: true-count calculation](https://www.qfit.com/CalculatingTrueCounts.htm) documents flooring, including negative quotients. Acewise consistently floors; it does not copy the introductory Wizard example's nearest-rounding convention.
- The two engine suites contain 32 tests covering totals, naturals versus ordinary/split 21, peek, S17/H17, split limits/aces, DAS, surrender eligibility, insurance, pushes/payouts, hidden-card independence, reachable scenarios, and stale action IDs.
- Counting/persistence suites contain 32 tests, including **36 complete drill configurations**: six modes × manual/automatic × three speeds. Independent rank/count calculations check answers, negative conversion, pause clocks, and recovery races.

Prior implementation fixes for rare shoe exhaustion and impossible custom split-ace histories remain covered by regressions. They are not counted here as newly discovered runtime engine bugs.

## Manually reconciled results

**Diagnostic:** four correct answers out of five displayed **80%**, with five unassisted first attempts. The three soft hands were correct; one of two pair hands was wrong. Replaying the wrong 5+5 versus 8 decision correctly did not alter 80% or the five-attempt denominator. One new correct similar-hand attempt then gave five correct out of six, displayed as approximately 83%.

**Counting:** a 52-card countdown with four submitted zeros had expected checkpoint values **+5, +1, 0, 0**. Review displayed **50% exact accuracy** and **1.50 mean absolute error**, matching `(5 + 1 + 0 + 0) / 4`. The ten-answer conversion session displayed 100% and zero error; negative examples included `−9 / 5.5 → −2` and `−10 / 3.5 → −3`.

**Virtual units:** ten rounds produced net changes **+4, +3, −2, −2, −1, +4, −2, −1, +4, −2**: total **+5**, ending balance **105** from 100. Review separately displayed **5/11 correct decisions (45%)**. The first doubled 11 became 21 and won four units after the dealer busted; the natural paid three on a two-unit wager. Learning accuracy remained separate from financial outcomes.

**Automated analytics oracle:** one correct answer in a one-answer session plus three wrong answers in another session aggregates to **1/4 = 25%**, rather than an average of session percentages. Count errors `0, +2, −1` yield one-third exact accuracy and mean absolute error 1; times 1s, 9s, 2s yield median 2s. Tests also cover assistance denominators, replay-only histories, recommended-action grouping, and heatmap missing values.

## Remaining limitations and prioritized improvements

1. **Before native release — test on physical iOS and Android.** Check safe areas, large system text, VoiceOver/TalkBack, focus order, native keyboards, background/cold-start restoration, offline startup, share export, haptics, and audible card sound. These checks would establish that the polished web experience also works comfortably on phones. No signed EAS build or physical-device session was performed here.
2. **Before release — complete the accessibility and navigation matrix.** Exercise onboarding skip/all goals, every chart tab at narrow widths, long content at enlarged text sizes, and end-to-end keyboard operation. A visible label or live-region declaration alone does not prove accessibility. No formal contrast audit was performed.
3. **Next engineering improvement — retain a small browser smoke suite in CI.** Cover diagnostic → results, settings pause/resume, split-card visibility, and restart after changing global rules. Current CI verifies domain logic and web bundling; route/rendering contracts still depend on manual checks. Add native bundle exports to CI if every change must validate all three bundles.
4. **Next learning improvement — user-test the first five minutes with beginners.** Measure whether learners can choose between lessons, isolated decisions, counting drills, and the full table without guidance. Use observed confusion to simplify setup and explain advanced controls progressively; this audit alone does not establish how novices understand the app.
5. **Later — deepen review only with explicit learning design.** The current refresher is a fixed seven-day reminder after a successful lesson check, tested at exact timestamp boundaries. A multi-stage spaced-review schedule would need additional history and a defined policy. Keep raw exported answers as the audit trail for future progress metrics.

Declared scope remains total-dependent basic strategy, six introductory deviations under documented rules, one simulated player seat, and virtual units. A complete index system, composition-dependent EV solver, cloud sync, additional seats, and count-based betting ramps are not implemented. Browser offline installation is also not provided; the web bundle has no service worker.
